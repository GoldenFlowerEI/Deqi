# Deqi v3.0 — 设计与路线图

> 目标:让 Deqi 变得**更聪明、更全能、更高效**。
> 本文先汇报研究 → 提炼 pattern → 对齐 Deqi 现状 → 给出 v3.0 架构 → 拆 v3.1-v3.5 五个 milestone。

---

## 0. TL;DR

Deqi v2.2.1 是一个 **ReAct + 子智能体 + Constitution + UserModel** 的本地桌面 agent,12 个工具、5 层
认知层、HTTP+WS server + Tauri 2 desktop。**最大的 gap** 不是"没有联网"那种表层能力,而是:

1. **没有长时记忆 / 跨 session 上下文** — 每次 New task 从零开始,scheduler 跑完了,user 不知道下次开机还在不在
2. **没有真正的规划器** — 一次 user_message 触发一次性 ReAct,没有"先 plan,再 step"
3. **没有正式的多 agent orchestration** — `subagent` 是单次委派,没有"主 agent 调度一群 specialists"
4. **没有 evaluation harness** — 我们不知道 v3.0 比 v2.2.1 好了多少
5. **tool schema 不够 self-describing** — Anthropic 反复强调"工具描述要像给初级工程师写的 docstring",我们大部分 tool 描述太简略

v3.0 的核心解法:**渐进式把 Deqi 从"ReAct 单 loop"升级到"initializer + coding agent + 多 agent + 持续 memory + 可评估"** — 跟 Anthropic 2025 年 11 月那篇
[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) 走的是同一条路,但加上 Deqi 七层哲学(huiguang、autopoiesis、society of mind、wu wei)做差异化。

## 1. 研究 — 我读到的 6 篇

| # | 来源 | 时间 | 一句话要点 |
|---|---|---|---|
| 1 | **Anthropic: *Building Effective Agents*** | 2024-12 | Augmented LLM 是基础;workflows(prompt chaining/routing/parallelization/orchestrator-workers)vs agents(动态决策);**"先 LLM API 直接用,框架别加抽象"**;tool design "poka-yoke" 要让模型很难写错。|
| 2 | **Anthropic: *Effective harnesses for long-running agents*** | 2025-11 | 跨多个 context window 的 long-running 任务需要两段式:**initializer agent**(建 init.sh / claude-progress.txt / git 初始 commit + JSON feature list)→ **coding agent**(每 session: pwd → 读 progress → 读 feature_list → git log → 选最高优先级 feature → 改 feature 的 `passes: false` → `passes: true`,每个 feature 必测,绝不删 test)。"It is unacceptable to remove or edit tests"。**清洁状态 = 可 merge 到 main 的状态**。|
| 3 | **ReAct** (Yao et al.) | 2022-10 (ICLR 2023) | 经典 Thought → Action → Observation loop;推理 traces 让 action plan 可被诱导/追踪/更新,actions 让模型接触外部;**ALFWorld +34%、WebShop +10% 超过 IL/RL baselines**。|
| 4 | **Generative Agents** (Park et al., Stanford) | 2023-04 | 25 个 agent 在 sandbox;**memory stream**(所有经验的自然语言记录)→ **reflection**(定期合成高层洞察)→ **plan**(动态检索);观察、规划、反思三个组件 ablation 后每个都关键缺失;情人节派对案例证明 emergent social behavior。|
| 5 | **awesome-agent-harness** (RUCAIBox, 2026) | 2026 | 把 harness 工程分成三层:① **Action Interface**(ReAct / Toolformer / Executable Code Actions)② **Workflow Infrastructure**(SWE-agent / OpenHands / Claude Code)③ **User-Centric Persistence**(OpenClaw / persistent memory / user profiles)。每层有自己的设计空间与代表系统。|
| 6 | **Anthropic: *Advanced tool use*** (2025-11) | 2025-11 | Tool search / programmatic tool calling / fine-grained tool streaming / tool use examples 四个新机制,让模型在 1000+ tools 的库下仍能正确选用。|

辅助读到的 6 个次要源:**Toolformer** (Meta, 2023, 自监督学用工具)、**Reflexion** (Shinn 2023, verbal self-critique 作为 episodic memory)、**Tree of Thoughts** (2023, 4% → 74% Game of 24)、**Voyager** (Minecraft 终身学习)、**MCP** (Anthropic 2024, 工具协议标准)、**Agent Skills** (Xu/Yan 2026, skill 库 + 安全管理)。

## 2. Pattern 提炼 — 7 个落地原则

从上面提炼出 7 个**反复出现**的设计原则,直接映射到 v3.0 的工程决策:

### P1. ReAct loop 是底盘,但要被"包"起来
每个 turn 都是 *Thought → Action → Observation* 循环(Deqi 已经有),但单 loop 永远跑不出"长任务"。必须:
- 外层加 **initializer / coding agent 二段式** (Anthropic 2025-11)
- 内层加 **plan-then-execute** (ReAct 论文 §4.2: 复杂任务先 plan 比直接 ReAct 高 27%)
- 加 **reflection** 在 turn_end (Generative Agents 三大支柱之一)

### P2. Tool schema 决定一切
**Anthropic 的 4 个教训**:
1. Tool 描述要"像给 junior engineer 写 docstring" — 包含 when to use, when NOT to use, edge cases
2. 工具的 input shape 越 poka-yoke(防呆),模型越用得对 — **"absolute path only"** 是经典例子
3. Tool 的 output 要 **token-efficient + model-readable** — 长响应要 truncation + 摘要标志
4. Tool **isConcurrencySafe** 标记必须准 — 我们已经做了,但 webFetch 之后要补更多

### P3. Memory 必须分三层,不是一锅端
学 Generative Agents + A-MEM + RAMPART:
- **Working memory**(per turn):当前 messages + tool state — 已经做了
- **Episodic memory**(per session):JSONL 会话记录 — 已经做了
- **Semantic memory**(cross-session):从 sessions 提炼的事实/偏好/任务模式 — **v3.0 重点**

关键洞察:不是把"所有 session 都记住",而是**主动遗忘 + 主动提炼**。Memory 越多越干扰。

### P4. 规划 ≠ 一步思考
复杂任务必须分两段:
- **Plan step**(一次,reasoning-heavy):把任务拆成 N 个 step,每 step 标注依赖
- **Execute steps**(N 次,action-heavy):每 step 用 ReAct 单独跑
Anthropic orchestrator-workers 就是这个。**v3.0 加 `plan` tool**。

### P5. 多 agent 不是越多越好
**Minsky 的 K-line + Maturana 的 distributed autonomy** 启示:
- 多数任务**一个 agent 就能干**,不要为多而多
- 当一个 turn 的 tool call 数 > 5,或 token 消耗 > 20K,**才**考虑 sub-agent
- Sub-agent 应该是"无状态 specialist":读输入、出结果、不记得别的
- 主 agent 是 K-line 的"协调者":决定调谁、合成结果、保留记忆

### P6. Persistence 是长任务的核心
Anthropic 2025-11 那篇反复强调:
- **每个 session 必须留 artifact**(init.sh、progress.txt、git commit)
- **State machine 必须可恢复** — server crash 后,下一个 session 从 progress.txt 接着来
- **Decision 是可审计的** — 每个 feature 改了什么、为什么、谁改的,都要 trace

### P7. Evaluation 先于一切
Anthropic 的 "Poka-yoke" 哲学应用于自己:用 SWE-bench Verified / WebArena / AgentBench 这类标准化 benchmark 测自己,而不是"我觉得好"。

## 5. v3.0 架构

### 5.1 三大变化

**(a) 两段式 harness**(Anthropic 2025-11 启示):

```
┌──────────────────────────────────────────────────────┐
│  deqi-server (long-running, 7×24)                     │
│  ┌──────────────────────────────────────────────┐    │
│  │  state machine (per-project, persistent)     │    │
│  │  - project.json: metadata, last progress     │    │
│  │  - progress.md: per-feature status           │    │
│  │  - init.sh: idempotent env setup             │    │
│  │  - memory/: long-term semantic memory        │    │
│  └──────────────────────────────────────────────┘    │
│       ▲                                                │
│       │ resume + summarize                            │
│       │                                                │
│  ┌─────────────┐  per-turn   ┌─────────────────────┐  │
│  │ initializer │──────────▶│  coding agent       │  │
│  │  (first run) │           │  (each session)    │  │
│  └─────────────┘            └─────────────────────┘  │
│                              │  uses                  │
│                              ▼                        │
│  ┌──────────────────────────────────────────────┐    │
│  │  12 + 3 = 15 tools (12 v2.2.1 + plan,        │    │
│  │  skill, eval) + per-project MCP servers       │    │
│  └──────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────┘
```

**(b) 记忆三层模型**(Generative Agents + RAMPART):

```
┌──────────────────────────────────────────────┐
│  Semantic memory (long-term, cross-session)   │
│  - facts.json: stable facts (paths, env)       │
│  - prefs.json: user preferences (model, style) │
│  - patterns.json: recurring task patterns     │
│  - skills/: reusable code + learned habits     │
│  [persisted in ~/.deqi/memory/]                │
│  [retrieved at session start + after every turn]│
└──────────────────────────────────────────────┘
           ▲ summary              ▼ retrieve
┌──────────────────────────────────────────────┐
│  Episodic memory (per-session)                │
│  - JSONL in ~/.deqi/sessions/<cwd>/<id>.jsonl│
│  - already have ✓ (v0.1+)                     │
└──────────────────────────────────────────────┘
           ▲ append              ▼ read
┌──────────────────────────────────────────────┐
│  Working memory (per-turn)                    │
│  - in-memory AgentState.messages[]            │
│  - already have ✓ (v0.1+)                     │
└──────────────────────────────────────────────┘
```

**(c) 新增 3 个 tool**:

| Tool | 名字 | 作用 | v 版本 |
|---|---|---|---|
| `plan` | plan  | 把任务拆成 steps (ReAct §4.2 orchestrator-workers) | v3.1 |
| `skill` | skill | 从 `~/.deqi/skills/` 加载/保存/调用已学技能 | v3.2 |
| `eval` | eval  | 跑 self-check:让 agent 复盘自己刚才的 turn,打分 | v3.4 |

### 5.2 全新的 system prompt 结构

v2.2.1 的 system prompt 只是 `buildSystemPrompt` 拼了一个字符串。v3.0 改成 **6 段** 显式结构,每段对应一个 v3 后的能力:

```
┌────────────────────────────────────────────────┐
│ §1. Role        (1-2 lines)                     │
│ §2. Environment (cwd, model, today, platform)  │
│ §3. Tools       (schema + examples + warn)      │
│ §4. Workflow    (initialize vs code, plan→exe)  │
│ §5. Memory      (when to write, when to read)   │
│ §6. Constitution (constitution tool on demand)  │
└────────────────────────────────────────────────┘
```

### 5.3 工具描述大重写

按 Anthropic 4 原则,每个工具的 description 改成:
```
<name>: <one-line summary>

When to use:
  - <case 1>
  - <case 2>

When NOT to use:
  - <case 1>  (use <other tool> instead)

Parameters:
  - param1: <type> — <description>
  - param2: <type> — <description> (default: ...)

Returns:
  - <what the model sees in the tool_result>

Examples:
  - <valid input> → <what happens>

Concurrency: <safe | not safe — why>
```

12 个 tool 全部重写(预计 v3.1)。

### 5.4 Memory API 设计

```ts
// semantic memory: 3 个 JSON 文件,读写用 fs
readFacts(cwd: string): Promise<Facts>
writeFacts(cwd: string, patch: Partial<Facts>): Promise<void>
readPrefs(): Promise<Prefs>             // global, not per-cwd
writePrefs(patch: Partial<Prefs>): Promise<void>
readPatterns(cwd: string): Promise<Pattern[]>
addPattern(cwd: string, p: Pattern): Promise<void>

// 工具: `memory` (集成上面的读写)
{
  name: 'memory',
  action: 'read' | 'write' | 'search',
  target: 'facts' | 'prefs' | 'patterns',
  ...
}
```

### 5.5 Scheduling 升级

v2.2.0 的 scheduler 只做"30s tick → 检查 cron-like cadence → 跑 prompt"。v3.0 加:
- **Initializer mode**:对一个 `init: true` 的 schedule item,跑 initializer agent(建 init.sh + progress.md + 首次 commit)
- **Resume mode**:如果 server 启动时检测到某个 project 有未完成 feature,自动起一个 coding session

## 6. 路线图 — v3.1 → v3.5

每个版本 = **1 个核心能力 + 1 个 test suite + commit + tag + memory**。

### v3.1 — Long-running harness + 工具描述大重写 (1.5 周)
**新能力**:
- `state/` 模块:`project.json` / `progress.md` / `init.sh` 三件套
- Initializer agent + coding agent 二段式 (orchestrator decides which to invoke)
- 12 个 tool description 全部按 Anthropic 4-原则重写
- Plan tool (`plan`):把用户输入拆成 steps,主 agent 按顺序跑

**测试**:
- `examples/smoke/v3.1-long-running.ts` — 模拟 server 跨 3 个 session 完成 5-feature 任务,断言每 session 后 init.sh 跑通 + progress.md 更新
- `examples/smoke/v3.1-tool-descriptions.ts` — 12 个 tool description 都有"when to use / when not / examples"段
- `examples/smoke/v3.1-plan.ts` — plan tool 把 "build a calculator" 拆成 5+ steps,每个 step 标依赖

**预期 asserts**: +60(总 285)

### v3.2 — Semantic memory + skills (1 周)
**新能力**:
- `~/.deqi/memory/{facts,prefs,patterns}.json` 自动维护
- `memory` tool (read/write/search)
- 每次 session_start 自动 retrieve top-K relevant facts
- `skill` tool — 从 `~/.deqi/skills/<name>/{SKILL.md, run.sh}` 加载,SKILL.md 描述 when/how,run.sh 可执行
- Session_end 跑一次 reflection,提炼新 facts 写入 memory

**测试**:
- `v3.2-memory.ts` — 跨 session 保留 facts,主 agent 在 turn 1 提到的事实在 turn 5 还能用
- `v3.2-skills.ts` — `skill_save` 写一个 hello-world skill,`skill_load` 后能 invoke

**预期 asserts**: +40(总 325)

### v3.3 — Multi-agent orchestration (1 周)
**新能力**:
- `orchestrator` 工具 — 主 agent 显式调度:plan → specialist sub-agents → synthesis
- 3 个内置 specialist: `code-reviewer` (读 git diff + 静态分析)、`test-runner` (跑 vitest/jest + 解析结果)、`doc-writer` (从代码生成 .md)
- Sub-agent 默认 sandboxed(只看主 agent 显式传入的 input + 自己目录),防止"看了不该看的东西"

**测试**:
- `v3.3-orchestrator.ts` — `orchestrator(subagent=code-reviewer, task="review last 3 commits")` 真实工作
- `v3.3-subagent-sandbox.ts` — sub-agent 试图读主 agent 不该给它的文件被拒

**预期 asserts**: +30(总 355)

### v3.4 — Self-evaluation + benchmark (1 周)
**新能力**:
- `eval` tool — agent 在 turn_end 自动跑"我刚做对了吗?给自己打分",分数写进 introspection log
- `bench/` 目录:scripts/bench-{swe-lite, webarena-lite, tool-use}.ts,跑标准化子集(SWE-bench Verified mini-splits, 50 cases)
- 每次 commit 跑一次 bench,结果存 `bench/runs/<commit>.json`
- 在 desktop status bar 加 "self-eval" 实时显示

**测试**:
- `v3.4-eval.ts` — eval tool 跑过后,introspection log 至少有一条 self-grade
- `v3.4-bench.ts` — bench script 能跑通且产出 JSON

**预期 asserts**: +25(总 380)

### v3.5 — MCP + browser/computer use (1.5 周,可选)
**新能力**:
- MCP 客户端(只读 + 调用,不开 server):`mcp` tool 让 agent 接入任意 MCP server
- `browser` tool (Playwright driver):`goto / click / type / screenshot / extract`
- `computer` tool (cross-platform GUI automation):`screenshot / click / type / scroll` (主要给 Windows + macOS)
- 安全:browser tool 的 `goto` 走 URL allowlist(默认 deny 私网 IP)

**测试**:
- `v3.5-mcp.ts` — 连一个 mock MCP server,tool list + tool call 工作
- `v3.5-browser.ts` — `browser.goto('https://example.com')` + `browser.extract('h1')` 拿到 "Example Domain"

**预期 asserts**: +30(总 410)

### 长期 (v4.0+)
- 训练自己的 tool-mastery(从 intospection snapshot 学)
- Huiguang 返光 UI:可视化 agent "注意力泄露"程度
- 多模态:截图、PDF、video 输入
- 跨设备同步(手机操控 v0 真的接通)

## 7. 度量 — 怎么知道 v3.x 比 v2.2.1 好

| 指标 | v2.2.1 baseline | v3.5 target |
|---|---|---|
| 跨 session 任务完成率(5-feature, 3-session 任务) | ~0%(没有 memory) | > 60% |
| 平均每 task 工具调用次数(同 prompt) | 8-15 | 5-8(更聚焦) |
| 长任务(>20 turn) 中 agent "重做之前工作" 的次数 | 3-5 | 0-1 |
| 工具调用错误率(input 错 / 不该调) | ~15% | < 5% |
| 跨 session 用户偏好记忆命中率 | ~0% | > 80% |
| Self-eval 分数(bench mini) | N/A | > 0.7 mean |
| 全套 test asserts | 225 | 410+ |
| Tests pass rate | 100% | 100% |
