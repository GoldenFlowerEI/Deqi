# Deqi v3.7 — "Hermes-Inspired" Design

**Tag**: v3.7.0 on `desktop-v2`
**Goal**: borrow the three highest-leverage patterns from Hermes Agent (Nous Research) — auto-retrieval, tool reflection, skill auto-suggestion. No new tools.

## What Hermes does that Deqi doesn't

| Pattern | Hermes | Deqi v3.6 | v3.7 |
|---|---|---|---|
| Auto-retrieval: pull relevant memory into every prompt | ✓ (semantic + recency) | explicit `memory search` only | added |
| Tool reflection: hint next step after each tool call | ✓ | none | added |
| Skill auto-suggestion: surface relevant skills at start | ✓ | none | added |
| Branching: explore N paths in parallel | ✓ | tools run concurrently but no "explore" semantics | light scaffolding (event only); full impl is v3.7.1 |
| Cross-session learning (embeddings) | ✓ | none | deferred (no embeddings infra yet) |
| Strict function-call JSON schema validation | ✓ | delegated to provider | deferred (provider-dependent) |

## v3.7 deliverables

### 1. Auto-retrieval (Hermes's "active memory" pattern)

**Before**: the agent has a `memory` tool but must remember to call it. Most agents don't.

**After**: at the start of every `run()` (first turn only — debounced), the agent:
1. Splits the user prompt into keywords
2. Asks the memory store for top 3-5 matching facts/patterns/prefs
3. Injects them as a `## Retrieved memory` block in the system prompt (or prepended to the user message — TBD by trial)
4. Emits a `memory_retrieved` event so the UI can show "I remember: ..."
5. Bumps `useCount` on each retrieved fact (so frequently-relevant facts bubble up)

**Implementation**:
- New `auto-retrieve.ts` in coding-agent: `retrieveRelevant(query: string, limit: number): RetrievalResult`
- Hook in `Agent.run()` before the first LLM call
- Per-session; debounced to once per `run()` call (so long multi-turn sessions don't re-retrieve every turn)

### 2. Tool reflection (Hermes's "post-action reflect" pattern)

**Before**: tool errors are returned as-is. The model has to figure out what to do.

**After**: after each tool call, before the next LLM call, a small `reflect` function:
- `isError` → suggests "the tool failed; consider X or Y"
- empty result (read returned nothing, grep found 0 matches) → suggests "consider a different tool or a wider query"
- success → no reflection (silent)

**Implementation**:
- New `reflection.ts`: `reflectOnTool(toolName, input, result): string | null`
- Called from `executeOneTool` after the tool returns
- The reflection is stored on the agent's state, then injected into the system prompt for the NEXT LLM call
- Emits a `reflection` event
- Persists to introspection log

### 3. Skill auto-suggestion

**Before**: the agent has a `skill` tool but must `skill list` to discover what's available, then `skill read` each.

**After**: at the start of every `run()`, the agent:
1. Reads the skill directory (`~/.deqi/memory/skills/`)
2. Scores each skill's description against the user prompt (keyword overlap)
3. Injects the top 1-3 matches as a `## Suggested skills` block
4. Emits a `skills_suggested` event

**Implementation**:
- New `skill-suggest.ts`: `suggestSkills(query: string, limit: number): SkillMatch[]`
- Hook in `Agent.run()` next to auto-retrieval
- Heuristic scoring: word overlap / description length. No embeddings yet.

## Non-goals (deferred to v3.7.1+)

- Cross-session pattern detection (needs embeddings)
- Strict function-call schema validation (provider-dependent)
- Full branching (multiple LLM calls in parallel, pick the best)
- Streaming sub-agent events to the desktop
- Real headless browser (Puppeteer/Playwright) for `browser.screenshot`

## Test plan

Three new test suites in `examples/smoke/`:

### `v3.7-auto-retrieve-test.ts` (~20 asserts)
- `retrieveRelevant` returns top N matches by keyword overlap
- empty memory → empty result
- exact match scores highest
- useCount is bumped on retrieval
- `## Retrieved memory` block is generated correctly
- debounce: retrieval happens once per `run()` even across multiple turns

### `v3.7-reflection-test.ts` (~15 asserts)
- `reflectOnTool` returns null for successful results
- `reflectOnTool` returns a hint for error results
- `reflectOnTool` returns a hint for empty results
- the reflection makes it into the next system prompt (smoke test)
- `reflection` event is emitted

### `v3.7-skill-suggest-test.ts` (~12 asserts)
- `suggestSkills` returns matches sorted by score
- empty skills directory → empty result
- exact keyword match wins
- top N limit works
- `## Suggested skills` block is generated

`v3.7.0` after all asserts pass + memory entry written.
